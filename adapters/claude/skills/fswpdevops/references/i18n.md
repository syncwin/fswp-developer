# Internationalization reference

## PHP functions

| Need | Function |
|---|---|
| Return a translated string | `__( 'Text', 'domain' )` |
| Echo it | `_e( 'Text', 'domain' )` |
| Return, escaped for HTML | `esc_html__( 'Text', 'domain' )` |
| Echo, escaped for HTML | `esc_html_e( 'Text', 'domain' )` |
| Return, escaped for an attribute | `esc_attr__( 'Text', 'domain' )` |
| With context (same word, different meaning) | `_x( 'Post', 'noun', 'domain' )`, `esc_html_x()`, `esc_attr_x()` |
| Singular or plural by number | `_n( '%s item', '%s items', $count, 'domain' )` |
| Plural with context | `_nx()` |
| Mark for extraction without translating now | `__()` variants at runtime; `_n_noop()` for later use |

Placeholders: use `%s`, `%d`, or numbered `%1$s` when order can change between languages.

```php
printf(
	/* translators: 1: number of items, 2: list name. */
	esc_html( _n( '%1$d item in %2$s', '%1$d items in %2$s', $count, 'my-domain' ) ),
	(int) $count,
	esc_html( $list_name )
);
```

## Loading translations

- Plugins hosted on WordPress.org use translate.wordpress.org; since WordPress 4.6 the plugin's text domain is loaded automatically for those. For other plugins call `load_plugin_textdomain( 'domain', false, dirname( plugin_basename( __FILE__ ) ) . '/languages' )` on `init` or later.
- Themes: `load_theme_textdomain( 'domain', get_template_directory() . '/languages' )` on `after_setup_theme` (classic themes).
- Confirm behavior for the target minimum WordPress version in the internationalization pages of the Plugin and Theme handbooks.

## JavaScript

```js
import { __, sprintf } from '@wordpress/i18n';
const label = sprintf( /* translators: %s: name */ __( 'Hello, %s', 'my-domain' ), name );
```

Register translations for a script with `wp_set_script_translations( $handle, 'my-domain', plugin_dir_path( __FILE__ ) . 'languages' )`. Blocks registered from block.json translate `title`, `description`, `keywords`, and variation strings when `textdomain` is set. Strings in `render.php` use the PHP functions.

## Making the template file

`wp i18n make-pot . languages/my-domain.pot` (command line). It scans PHP and JS; verify block.json and pattern headers are included. Keep the `.pot` in the repo or generate it in the release step.

## Common mistakes to flag

- Variable or constant passed as the text domain or the string.
- Sentence built from pieces (`__('You have ') . $n . __(' items')`).
- Missing translator comments on placeholder strings.
- `__()` used where an escaping variant is needed (or escaping missing entirely).
- Hard-coded English in JavaScript, block markup, or `alt` text.
- Date and number formats hard-coded instead of `wp_date()`, `number_format_i18n()`.
