# Theme directory requirements, in plain language

Source: Themes Team Handbook, "Required" page (updated 2026-06-09 when checked 2026-09-28). A theme must meet all of it; three or more distinct issues can lead to closure and resubmission after fixes.

1. **Licensing and copyright:** GPL-compatible for everything in the zip; "GPLv2 or later" recommended. Copyright information for the theme; license, copyright, and source for every bundled font or image (public-domain items excluded); one file listing all resources; all code and design must be yours or legally yours (no cloned designs); front-end copyright text shows the site owner's, not the author's.
2. **Privacy:** any tracking or data collection is off by default and opt-in, documented in `readme.txt`.
3. **Accessibility:** a skip link when there is something to skip (block themes get it on `<main>` automatically); visible keyboard focus in menus, form fields, buttons, and links; everything reachable and usable by keyboard on every screen size. The "accessibility-ready" tag adds further requirements.
4. **Code:** no PHP or JavaScript errors, warnings, or notices; secure (validate and sanitize input, escape output); no deprecated functions or constants; unique prefix of at least four letters for everything in the public namespace (options, functions, globals, constants, meta, script and style handles you author, image sizes, pattern categories). Third-party asset handles and menu/sidebar IDs are exempt.
5. **Functionality:** admin notices use the `admin_notices` API and are dismissible; do not paywall WordPress features, hide the admin bar, redirect on activation or alter activation, or remove non-presentational hooks (for example generator, feed links, REST discovery, oEmbed discovery, canonical, shortlink). **Do not include** custom post types, custom blocks, custom roles, user contact methods, custom mime types, shortcodes, or any functionality unrelated to design and presentation. Do not manipulate the directory preview.
6. **Plugins:** may only recommend plugins hosted on WordPress.org; installation only by user action; no bundled plugin zips or plugin functionality. Plugin territory examples: analytics, SEO options, contact forms, non-design meta boxes, resource caching, social buttons, session tampering.
7. **Naming and trademarks:** names must not use "WordPress", "Theme", or "Twenty*"; spell WordPress correctly in public text; no trademark violations; no WordPress logo in the theme logo or banner; the team can reject confusing names.
8. **Language and i18n:** all strings translatable with gettext (HTML template files are a temporary exception); the theme slug is the text domain and is declared in `style.css`; at most two text domains when a framework requires one.
9. **Files:** complete at submission; remove `.git`/`.svn`/`.hg`/`.bzr`, zip files, hidden files, and disallowed files (for example thumbs.db, desktop.ini, php.ini, error_log, web.config, `.sql`, `__MACOSX`, `.sh`, `.xml` other than wpml-config.xml, loco.xml, phpcs.xml, favicon.ico); one line-ending style; **no remote resources without user consent** (no CDNs; Google Fonts is the stated exception, though bundling fonts locally is the safer choice and this plugin's default); original files included when minified files ship; use WordPress's bundled libraries; images must not promote hate or violence or show recognizable children; screenshot no larger than 1200x900 pixels with a 4:3 ratio and must not look like an advertisement.
   - **Required `style.css` headers:** Theme Name, Author, Description, Version (X.X or X.X.X), Requires at least (X.X), Tested up to (X.X), Requires PHP (X.X), License, License URI, Text Domain. Theme URI and Author URI are optional and must be relevant. A valid `readme.txt` is required.
10. **Classic themes:** valid DOCTYPE and `language_attributes()`; `get_template_part()`/`locate_template()` for custom parts; correct front-page display; the `edit_theme_options` capability for option permissions; must include `wp_head()`, `body_class()`, `wp_footer()`, `wp_body_open()`, `post_class()`, `wp_link_pages()`, and `add_theme_support( 'title-tag' )` and `'automatic-feed-links'`; standard templates called by `get_header()`, `get_footer()`, `get_sidebar()`, `get_search_form()`.
11. **Block themes:** `style.css`, `readme.txt`, `theme.json`, and `templates/index.html`; block templates complete with correct opening and closing block tags.
12. **Settings pages and onboarding:** custom messages through `admin_notices`, one-time or permanently dismissible, no popups on activation; optional sub-pages under Appearance using core UI, scripts and styles loaded only on their pages (`admin_enqueue_scripts` with `$hook_suffix`); capability checks (`current_user_can()`, `canUser`); the Settings and Options APIs, with a **single option** (an array) prefixed with the theme slug; sanitize everything saved; not allowed in admin menus or onboarding: demo imports, external calls, tracking or affiliate links.
13. **Selling, credits, links, spam:** at most one front-end credit link to the Theme URI or Author URI plus one to WordPress.org; no obtrusive upselling, none on the front end; disclose affiliates; no spam in descriptions, readmes, starter content, or translation files.
14. **Author and upload rules:** one new theme submission at a time (updates unlimited); names cannot be reserved; themes you distribute elsewhere must be 100% GPL-compatible and say so; disclose secondary author accounts (more than one open ticket across accounts leads to closure and upload bans).
